# Handoff

다음 세션이나 다른 에이전트가 현재 작업을 최소한의 재탐색으로 이어갈 수 있도록, 한국어로 continuation-ready 핸드오프를 작성한다. 목표는 "요약"이 아니라 **작업 재개에 필요한 상태 보존**이다.

## Codex 실행 환경 지침

- 상태 확인은 `git status`, `git diff --stat`, `rg --files`, `sed -n` 같은 셸 명령으로 수행한다.
- `Read`, `Grep`, `Glob`, `Bash`, `Write` 같은 Claude Code 도구명은 개념적 단계로 해석하고 현재 세션의 Codex 도구로 대응한다.
- 저장 위치가 지정되지 않으면 파일을 만들지 말고 채팅에 핸드오프를 출력한다.

기술 식별자(파일 경로, 명령어, 브랜치명, 이슈 키, 함수명, 에러 메시지)는 번역하면 정밀도가 떨어지므로 원문을 유지한다.

이 스킬은 현재 상태를 **읽어서 기록**하는 것이 전부다. 코드 수정·커밋 같은 실제 작업은 수행하지 않으며, 사용자가 저장 위치를 지정한 경우에만 핸드오프 파일을 기록한다.

## 사용 상황

사용자가 다음과 같은 의도를 보이면 이 스킬을 사용한다.

- 다음 세션에서 이어서 작업하려고 함
- 다른 에이전트나 사람에게 현재 상태를 넘기려고 함
- 긴 작업을 중단하기 전에 맥락을 보존하려고 함
- "핸드오프", "인수인계", "맥락 이어가기", "다음 세션", "resume", "continue" 같은 표현을 사용함

## 사용하지 않을 때

다음 경우에는 이 스킬을 쓰지 않는다.

- **단순 대화·내용 요약**이 목적일 때 — 일반 요약으로 처리한다. 이 스킬은 후속 실행자가 바로 작업을 *재개*하도록 상태를 보존하는 게 목적이다.
- **실제 작업 수행**(코드 수정, 커밋, 파일 생성, 상태를 바꾸는 명령 실행)을 원할 때 — 이 스킬은 상태를 읽어 기록할 뿐 작업을 진행하지 않는다.
- 이어갈 맥락이 없는 **단발성 질문·설명**일 때.

## 워크플로우

1. **재개 대상 파악**
   - 대상이 미래 세션, 다른 에이전트, 사용자 본인, 협업자인지 확인한다.
   - 별도 요청이 없으면 한국어로 작성한다.
   - 사용자가 저장 위치를 지정하면 그 위치에 저장한다. 지정이 없으면 채팅에 제공한다.

2. **관련 상태만 수집**
   - 현재 목표, 최신 사용자 지시, 중간에 바뀐 방향을 확인한다.
   - 가능하면 `git status`, 변경 파일, 실행한 명령, 테스트 결과, 생성 산출물, 막힌 지점, TODO를 확인한다.
   - 검증하지 않은 내용은 검증했다고 쓰지 않는다.

3. **사실과 추론 분리**
   - 완료한 일은 파일, 명령 결과, 대화 기록 등 근거가 있을 때만 완료로 적는다.
   - 추론이나 가정은 명시적으로 표시한다.
   - 미결 질문과 위험을 숨기지 않는다.

4. **첫 행동을 분명히 제시**
   - 다음 세션에서 가장 먼저 할 단 하나의 행동을 쓴다.
   - 관련 파일 경로와 명령어를 정확히 적는다.
   - 되돌리면 안 되는 사용자 변경이나 unrelated dirty worktree 변경을 강조한다.

## 출력 형식

사용자가 다른 형식을 요청하지 않으면 아래 구조를 따른다.

```markdown
# 핸드오프

## 재개 프롬프트
[다음 세션에 그대로 붙여넣을 수 있는 짧은 프롬프트. 이 핸드오프를 읽고 현재 상태에서 이어가라고 말한다.]

## 목표
[원래 목표와 현재 목표. 중간에 방향이 바뀌었다면 함께 적는다.]

## 현재 상태
[작업이 지금 어디에서 멈췄는지 정확히 적는다.]

## 완료한 일
[완료된 항목을 글머리표로 적는다. 모든 세부 과정을 나열하지 말고 중요한 구현 내용만 포함한다.]

## 남은 일
[아직 끝나지 않은 작업을 실제 실행 순서에 맞춰 적는다.]

## 주요 파일 / 산출물
[관련 파일 경로, 생성된 결과물, 브랜치, PR, 티켓, 노트 등을 적는다.]

## 실행한 명령 / 검증
[실행한 명령과 결과를 적는다. 실패하거나 건너뛴 검증도 포함한다.]

## 결정사항 / 가정
[작업 중 내린 결정, 수용한 제약, 다음 세션이 유지해야 할 가정을 적는다.]

## 위험 / 주의사항
[알려진 위험, 막힌 지점, 되돌리면 안 되는 사용자 변경, 취약한 영역, 오해될 수 있는 맥락을 적는다.]

## 다음 행동
[다음 세션에서 가장 먼저 해야 할 단 하나의 행동을 적는다.]
```

## 재개 프롬프트 예시

```text
아래 핸드오프를 읽고 현재 상태에서 작업을 이어가줘. 먼저 다음 행동부터 시작하고, 결정사항을 유지하며, 관련 없는 사용자 변경은 되돌리지 마.
```

```text
아래 핸드오프를 기준으로 이 작업을 계속해줘. 먼저 현재 git/워크스페이스 상태를 확인한 뒤 남은 일을 순서대로 진행해.
```

## 품질 체크리스트

핸드오프를 전달하기 전에 다음 항목을 확인한다.

- 명확한 현재 목표가 있는가?
- 정확한 작업 중단 지점이 있는가?
- 구체적인 다음 행동이 있는가?
- 관련 파일 경로와 산출물이 있는가?
- 건너뛰거나 실패한 검증을 포함한 검증 상태가 있는가?
- 다음 세션에 이어져야 할 결정사항과 가정이 있는가?
- 위험, 막힌 지점, dirty worktree 주의사항이 있는가?
- 완료한 작업이나 테스트 결과에 대한 근거 없는 주장이 없는가?

## 스타일

간결하되 맥락 손실은 없어야 한다. 긴 설명보다 짧은 글머리표를 우선한다. 작업 세부사항은 구체적으로 쓰고, 전체 대화록을 다시 쓰는 형태는 피한다.
