# 문서 검수 리포트 템플릿

리포트 작성 시 아래 구조를 따른다. `[대괄호]` 안의 내용은 실제 검수 결과로 대체한다.

## 단일 문서 검수 리포트

```markdown
# 문서 검수 리포트: [문서 제목]

> 검수일: YYYY-MM-DD
> 대상 문서: [파일 경로]
> 참고 문서 URL: N개

---

## 요약

| 판정 | 건수 |
|------|------|
| 정확 | N |
| 수정 필요 | N |
| 오류 | N |
| 누락 | N |
| 검증 불가 | N |

---

## 1. 정확성 검증 결과

### 정확한 내용

- (공식 문서와 일치하는 내용 요약 -- 별도 수정 불필요)

### 수정 필요

**[항목 제목]**
- **가이드 내용**: (현재 가이드에 작성된 내용)
- **공식 문서 내용**: (공식 문서의 현재 내용)
- **수정 제안**: (어떻게 고치면 되는지)
- **참고**: [출처](URL)

### 오류

**[항목 제목]**
- **가이드 내용**: (잘못된 내용)
- **공식 문서 내용**: (올바른 내용)
- **수정 제안**: (올바른 내용으로 교체)
- **참고**: [출처](URL)

---

## 2. 변경된 내용

공식 문서가 업데이트되어 가이드에 반영이 필요한 항목:

**[변경 항목 제목]**
- **현재 가이드**: (가이드의 현재 설명)
- **공식 문서 변경 사항**: (무엇이 어떻게 바뀌었는지)
- **권장 조치**: (가이드에서 어떻게 업데이트하면 되는지)
- **참고**: [출처](URL)

---

## 3. 누락된 내용

공식 문서에는 있으나 가이드에서 다루지 않은 핵심 내용:

**[누락 항목 제목]**
- **공식 문서 내용**: (누락된 내용 요약)
- **추가 위치 제안**: (가이드의 어느 섹션에 추가하면 좋을지)
- **참고**: [출처](URL)

---

## 4. URL 유효성

| # | 참고 문서 | URL | 상태 |
|---|-----------|-----|------|
| 1 | [문서명] | URL | 유효 / 리다이렉트 / 404 / 접근 불가 |

---

## 5. 개선 제안 (선택)

오류는 아니지만 추가하면 문서 품질이 높아질 내용 (1~3개 이내):

- (예: "공식 문서에 새로 추가된 예시가 있어 가이드에도 포함하면 이해에 도움이 됩니다")

> 개선 제안은 문서의 주제 범위를 벗어나지 않는 선에서만 제안한다.
```

## 전체 검토 시 종합 리포트 (앞에 추가)

전체 문서 검토 시, 개별 리포트 앞에 아래 종합 리포트를 먼저 배치한다.

```markdown
# 전체 문서 검수 종합 리포트

> 검수일: YYYY-MM-DD
> 검토 문서: N개

---

## 종합 요약

| 문서 | 정확 | 수정 필요 | 오류 | 누락 | 검증 불가 |
|------|------|-----------|------|------|-----------|
| [문서명] | N | N | N | N | N |
| ... | | | | | |
| **합계** | **N** | **N** | **N** | **N** | **N** |

## 시급 업데이트 TOP 3

1. **[문서명]** -- (이유: 오류 N건, 주요 변경 사항 설명)
2. **[문서명]** -- (이유)
3. **[문서명]** -- (이유)

---

(이하 각 문서별 상세 리포트)
```
