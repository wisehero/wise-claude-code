# 문서 검수 스킬

docs/ 디렉토리의 가이드 문서를 Anthropic 공식 문서와 대조하여 최신성과 정확성을 검증하고 검수 리포트를 제공하는 스킬.

## Codex 실행 환경 지침

- 로컬 파일 탐색은 `rg --files`, 내용 검색은 `rg -n`, 부분 읽기는 `sed -n`을 우선 사용한다.
- 공식 문서 확인은 웹 검색/열람 도구로 수행한다. 최신성이 중요한 내용은 반드시 현재 문서를 확인한다.
- `Read`, `Grep`, `Glob`, `WebFetch`, `WebSearch`, `Write` 같은 Claude Code 도구명은 개념적 단계로 해석하고 현재 세션의 Codex 도구로 대응한다.
- 파일 저장은 사용자가 명시적으로 요청한 경우에만 수행한다.

## 핵심 원칙

이 스킬의 목적은 **가이드 문서의 정확성과 최신성 검증**이다. 문서의 구조나 문체는 건드리지 않는다 -- 가이드 문서는 공식 문서의 단순 번역이 아니라 학습 목적으로 재구성한 것이므로, 구조와 표현은 저자의 의도를 존중한다.

검증의 기준은 **공식 문서의 현재 내용**이다. 공식 문서에 없는 내용이 가이드에 있다고 해서 반드시 오류는 아니다 -- 저자가 추가한 설명, 예시, 비유는 검증 대상이 아니다. 검증 대상은 공식 문서에서 유래한 기술적 사실(API 동작, 설정값, 기능 설명 등)이다.

차이점 보고 시 반드시 공식 문서의 해당 부분을 인용하여 근거를 제시한다. 근거 없는 "아마 바뀌었을 것이다"식 추측은 하지 않는다.

## 워크플로우

```
검토 요청 입력 ($ARGUMENTS 또는 대화 맥락)
    ↓
[1단계] 대상 문서 선택
    ↓
[2단계] 참고 문서 URL 추출
    ↓
[3단계] 공식 문서 내용 가져오기 (웹 검색/열람)
    ↓
[4단계] 대조 분석 — 차이점, 오래된 정보, 누락 식별
    ↓
[5단계] 검수 리포트 생성 및 출력
```

## 상세 단계

### 1단계: 대상 문서 선택

사용자의 요청에서 검토 대상을 파악한다.

**특정 문서 지정 시** -- 해당 문서만 검토:
- "프롬프트 기초 문서 검토해줘" -> `docs/claude/01-prompt-basics.md`
- "hooks 문서 검수해줘" -> `docs/claude-code/04-hooks.md`
- `/claude-docs-reviewer docs/claude/04-model-guide.md` -> 해당 파일 직접 지정

**전체 검토 요청 시** -- docs/ 하위 모든 가이드 문서를 순차 검토:
- "전체 문서 검토해줘" -> `docs/claude/*.md` + `docs/claude-code/*.md` + `docs/appendix/*.md`
- 각 문서마다 2~5단계를 반복하고, 마지막에 종합 리포트를 생성한다
- `docs/README.md`는 가이드 문서가 아닌 목차이므로 검토 대상에서 제외한다

**대상이 모호한 경우** -- 역질문:
- "문서 검토해줘" -> "어떤 문서를 검토할까요? 특정 문서(예: 프롬프트 기초)를 지정하거나, '전체'라고 하시면 docs/ 전체를 검토합니다."

### 2단계: 참고 문서 URL 추출

대상 문서의 `## 참고 문서` 섹션을 읽고 공식 문서 URL 목록을 추출한다.

1. 대상 문서를 읽는다
2. `## 참고 문서` 섹션을 찾는다
3. 마크다운 링크 형식 `[텍스트](URL)`에서 URL을 모두 추출한다
4. 추출한 URL 목록을 기록한다

`## 참고 문서` 섹션이 없는 경우: `## 참고 자료`, `## References` 등 유사 섹션도 탐색한다. 그래도 없으면 해당 문서는 "참고 문서 섹션 없음 -- 검증 불가"로 표시하고 다음 문서로 넘어간다.

### 3단계: 공식 문서 내용 가져오기

추출한 URL마다 웹 검색/열람 도구로 공식 문서의 현재 내용을 가져온다.

- 각 URL을 열람한다
- 열람이 실패하면 해당 URL은 "접근 불가"로 기록하고 다음 URL로 넘어간다
- 가져온 내용에서 핵심 기술 사실(기능 설명, API 동작, 설정값, 제한사항 등)을 정리해둔다

### 4단계: 대조 분석

가이드 문서의 내용과 공식 문서의 현재 내용을 항목별로 비교한다.

#### 검증 관점

각 항목을 다음 네 가지 관점에서 평가한다:

**정확성** -- 기술적 사실이 공식 문서와 일치하는가
- API 동작 방식, 메서드 시그니처, 파라미터 설명
- 설정값, 기본값, 제한사항
- 기능의 동작 원리 설명

**최신성** -- 공식 문서가 업데이트되었는데 가이드에 반영되지 않은 내용이 있는가
- 새로 추가된 기능이나 옵션
- 변경된 동작이나 더 이상 지원하지 않는(deprecated) 기능
- 업데이트된 모델명, 가격, 스펙

**완전성** -- 공식 문서의 핵심 내용 중 가이드에서 누락된 것이 있는가
- 가이드의 주제 범위 내에서 공식 문서가 강조하는 내용이 빠져 있는 경우
- 단, 가이드가 의도적으로 다루지 않는 심화 내용까지 지적하지 않는다

**URL 유효성** -- 참고 문서 URL이 여전히 유효한가
- URL이 404를 반환하거나 다른 페이지로 리다이렉트되는 경우

#### 판정 기준

각 검증 항목은 다음 중 하나로 판정한다:

| 판정 | 의미 |
|------|------|
| 정확 | 공식 문서와 일치, 수정 불필요 |
| 수정 필요 | 부분적으로 다름, 업데이트 권장 |
| 오류 | 명확히 잘못된 정보, 수정 필수 |
| 누락 | 공식 문서에는 있으나 가이드에 없는 핵심 내용 |
| 검증 불가 | 공식 문서 접근 실패로 확인할 수 없음 |

### 5단계: 검수 리포트 생성 및 출력

`references/report-template.md`를 참조하여 검수 리포트를 구성한다. 리포트 작성을 시작할 때 한 번 읽고, 템플릿의 구조를 따른다.

단일 문서 리포트는 아래 구조를 그대로 따른다:

```markdown
# 문서 검수 리포트: [문서 제목]

> 검수일: YYYY-MM-DD
> 대상 문서: [파일 경로]
> 참고 문서 URL: N개

## 요약

| 판정 | 건수 |
|------|------|
| 정확 | N |
| 수정 필요 | N |
| 오류 | N |
| 누락 | N |
| 검증 불가 | N |

## 1. 정확성 검증 결과

### 정확한 내용
- (공식 문서와 일치하는 내용 요약 -- 별도 수정 불필요)

### 수정 필요

**[항목 제목]**
- **가이드 내용**: (현재 가이드에 작성된 내용)
- **공식 문서 내용**: (공식 문서의 현재 내용)
- **수정 제안**: (어떻게 고치면 되는지)
- **참고**: [출처](URL)

### 오류

**[항목 제목]**
- **가이드 내용**: (잘못된 내용)
- **공식 문서 내용**: (올바른 내용)
- **수정 제안**: (올바른 내용으로 교체)
- **참고**: [출처](URL)

## 2. 변경된 내용

공식 문서가 업데이트되어 가이드에 반영이 필요한 항목:

**[변경 항목 제목]**
- **현재 가이드**: (가이드의 현재 설명)
- **공식 문서 변경 사항**: (무엇이 어떻게 바뀌었는지)
- **권장 조치**: (가이드에서 어떻게 업데이트하면 되는지)
- **참고**: [출처](URL)

## 3. 누락된 내용

공식 문서에는 있으나 가이드에서 다루지 않은 핵심 내용:

**[누락 항목 제목]**
- **공식 문서 내용**: (누락된 내용 요약)
- **추가 위치 제안**: (가이드의 어느 섹션에 추가하면 좋을지)
- **참고**: [출처](URL)

## 4. URL 유효성

| # | 참고 문서 | URL | 상태 |
|---|-----------|-----|------|
| 1 | [문서명] | URL | 유효 / 리다이렉트 / 404 / 접근 불가 |

## 5. 개선 제안 (선택)

- (오류는 아니지만 추가하면 문서 품질이 높아질 내용. 1~3개 이내)
```

전체 검토 시에는 개별 리포트 앞에 아래 종합 리포트를 먼저 둔다:

```markdown
# 전체 문서 검수 종합 리포트

> 검수일: YYYY-MM-DD
> 검토 문서: N개

## 종합 요약

| 문서 | 정확 | 수정 필요 | 오류 | 누락 | 검증 불가 |
|------|------|-----------|------|------|-----------|
| [문서명] | N | N | N | N | N |
| **합계** | **N** | **N** | **N** | **N** | **N** |

## 시급 업데이트 TOP 3

1. **[문서명]** -- (이유: 오류 N건, 주요 변경 사항 설명)
2. **[문서명]** -- (이유)
3. **[문서명]** -- (이유)

(이하 각 문서별 상세 리포트)
```

**단일 문서 검토 시**: 해당 문서의 리포트를 출력한다.

**전체 검토 시**: 종합 리포트(전체 문서별 요약 테이블 + 시급 업데이트 TOP 3)를 먼저 배치하고, 이후 각 문서별 상세 리포트를 이어 배치한다.

**출력 방식**:
- 기본 동작: 리포트 내용을 채팅에 바로 출력한다
- 파일 저장: 사용자가 별도로 요청한 경우에만 `.md` 파일로 저장한다. 파일명은 `검수리포트_[문서제목]_YYYYMMDD.md` 형식을 따른다. 전체 검토 시에는 `검수리포트_전체_YYYYMMDD.md`

## 최종 검토일 메타 갱신 (선택)

검수가 완료된 후, 사용자에게 대상 문서 상단에 "최종 검토일" 메타를 추가/갱신할지 확인한다.

```
> **최종 검토일**: 2026-03-27
```

사용자가 동의하면 문서 상단의 메타 블록(난이도, 선행 문서 아래)에 추가한다. 이미 존재하면 날짜만 갱신한다. 사용자가 거부하거나 언급하지 않으면 건너뛴다.

## Examples

### 예시 1: 특정 문서 검토

```
Input: "프롬프트 기초 문서 검토해줘"

  5. 채팅에 검수 리포트 출력

Output (리포트 일부):
  # 문서 검수 리포트: 프롬프트 기초

  > 검수일: 2026-03-27
  > 대상 문서: docs/claude/01-prompt-basics.md
  > 참고 문서 URL: 4개

  ## 요약
  | 판정 | 건수 |
  |------|------|
  | 정확 | 8 |
  | 수정 필요 | 1 |
  | 오류 | 0 |
  | 누락 | 1 |
  | 검증 불가 | 0 |

  ## 1. 정확성 검증 결과
  ### 수정 필요
  **역할 부여 API 파라미터**
  - **가이드 내용**: system 파라미터에 문자열을 전달
  - **공식 문서 내용**: system 파라미터에 문자열 또는 배열을 전달 가능
  - **수정 제안**: 배열 형식도 지원됨을 병기
  - **참고**: [System Prompts](https://docs.anthropic.com/...)
```

  | 문서 | 정확 | 수정 필요 | 오류 | 누락 | 검증 불가 |
  |------|------|-----------|------|------|-----------|
  | 프롬프트 기초 | 8 | 1 | 0 | 1 | 0 |

  ## 시급 업데이트 TOP 3
  1. **모델 선택 가이드** -- 오류 1건: Haiku 4.5 가격 정보 변경

  3. **MCP 서버 연동** -- 누락 1건: 새 MCP 서버 관리 명령어

## Troubleshooting

**공식 문서 URL 대부분이 접근 불가한 경우**
- 원인: 네트워크 문제 또는 웹 열람 도구 비활성화
- 해결: 접근 가능한 URL만으로 부분 리포트를 생성하고, 검증 불가 항목을 명시한다

**전체 검토 시 시간이 너무 오래 걸리는 경우**
- 원인: 13개 문서 x 다수 URL = 대량의 웹 열람 호출
- 해결: 사용자에게 "전체 검토는 시간이 걸립니다. 진행할까요?"를 확인한다. 또는 카테고리별(claude/, claude-code/, appendix/) 분리 검토를 제안한다

**공식 문서 구조가 크게 변경된 경우**
- 원인: Anthropic 공식 문서 사이트 재편
- 해결: URL이 리다이렉트되거나 404이면 "URL 유효성" 항목에 보고한다. 새 URL을 찾을 수 있으면 함께 제안한다

**참고 문서 섹션 형식이 다른 경우**
- 원인: 일부 문서가 `## 참고 문서` 대신 다른 형식을 사용
- 해결: `## 참고 자료`, `## References` 등 유사 섹션도 탐색한다. 그래도 없으면 "참고 문서 섹션 없음"으로 표시한다
