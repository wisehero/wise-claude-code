# 검수 리포트 템플릿

리포트 작성 시 아래 구조를 따른다. `[대괄호]` 안의 내용은 실제 검수 결과로 대체한다.

````markdown
# 검수 리포트: [노션 페이지 제목]

> 검수일: YYYY-MM-DD
> 원본 페이지: [노션 링크]

---

## 요약

- AI투 수정: N건
- 오타 수정: N건
- 팩트체크 항목: N건 (정확 N / 부분수정 N / 오류 N)

---

| 2   | 오타 | "인터패이스"                 | "인터페이스"        | 오탈자                      |

## 3. 보완 제안 (선택)

노트 내용 자체에는 오류가 없지만, 추가하면 이해에 도움이 될 내용:
- (예: "Spring Boot 3.2부터 virtual thread 지원이 기본 포함되었으므로 한 줄 언급 추가 권장")

> 보완 제안은 원본에 **오류가 없지만** 한 줄 추가하면 이해가 풍부해지는 내용만 올립니다. 팩트 오류·부분수정은 위의 `팩트체크 결과` 섹션에 기록합니다. 제안은 1~3개 이내로 제한합니다.

---

## 부록: 직접 수정 프리뷰 모드 (원본 직접 수정 경로에서만 추가)

사용자가 원본 직접 수정을 요청한 경우, 위 리포트 형식 뒤에 아래 두 섹션을 **이어붙여** 출력한다. 프리뷰는 파일 편집 / Notion 업데이트 전에 사용자의 확인을 받기 위한 것이므로, 어떤 변경이 어떤 순서로 적용될지 한 눈에 보이도록 구성한다.

### 적용 예정 변경 목록

| #   | 유형 | 대상 (before)                  | 적용 후 (after)        | 근거                 |
| --- | ---- | ------------------------------ | ---------------------- | -------------------- |
| 1   | AI투 | "~는 매우 중요한 개념입니다"   | "~는 핵심 개념이다"    | K5 불필요한 강조     |
| 2   | 팩트 | "String 최대 크기는 1GB이다"   | "최대 크기는 512MB이다" | redis.io/docs/strings |
| 3   | 오타 | "데이타"                       | "데이터"               | 외래어 표기법        |

- 스타일 수정과 팩트 수정을 **한 표에 섞어서** 나열한다. 단, `유형` 컬럼은 `AI투 / 오타 / 팩트` 중 하나를 반드시 표기해 판단 근거가 갈리게 한다.
- `대상`과 `적용 후`는 파일 편집에 그대로 쓸 수 있는 원문 스니펫으로 구성한다 — 프리뷰가 실행 계획 역할까지 겸하기 때문이다.

### 확인 응답 프로토콜

변경 목록을 출력한 뒤, 아래 세 가지 응답 경로를 사용자에게 명시적으로 제시한다:

- **`진행`** — 목록의 모든 변경을 순서대로 적용.
- **`1, 3, 6만 진행`** 같은 **번호 선별** — 지정 번호만 적용, 나머지는 버림.
- **`취소`** — 어떤 편집도 수행하지 않고 종료.

응답이 이 셋 중 하나가 아니면 한 번 더 선택지를 제시한다. "응", "오케이", "좋아" 같은 모호한 동의만으로 전체 편집을 실행하지 않는다 — 되돌리기 어려운 경로이므로 명시적 키워드 매칭이 필요하다.
````
