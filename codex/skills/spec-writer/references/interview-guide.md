# 인터뷰 가이드

인터뷰 단계별 질문 참고 자료. 도메인에 따라 적절한 질문을 선택하여 활용한다. 모든 질문을 던지는 것이 아니라, 상황에 맞는 질문만 골라서 사용한다.

---

## 1단계: 프로젝트 개요 — 도메인별 추가 질문

### 웹 서비스

- 이 서비스의 주요 수익 모델은? (광고, 구독, 거래 수수료 등)
- 기존에 유사한 서비스를 사용하고 있었나? (마이그레이션 필요 여부 파악)

### 모바일 앱

- iOS/Android 모두 지원하나, 한쪽만 우선인가?
- 오프라인 사용이 필요한가?

### 내부 시스템 / 백오피스

- 현재 이 업무를 어떻게 처리하고 있나? (수작업, 엑셀, 레거시 시스템 등)
- 이 시스템에 접근할 수 있는 사람의 범위는?

### API / 플랫폼

- API를 소비하는 주요 클라이언트는? (자체 프론트엔드, 파트너사, 공개 API 등)
- API 버저닝 정책이 필요한가?

---

## 2단계: 기능 요구사항 — 심화 질문

기능을 더 구체화하기 위해 각 기능마다 물어볼 수 있는 질문들:

### 인증/인가 관련

- 소셜 로그인을 지원하나? (Google, GitHub, Kakao 등)
- 역할(Role) 기반 접근 제어가 필요한가? 어떤 역할이 있는가?
- 비밀번호 정책은? (최소 길이, 복잡도, 만료 기간)

### 데이터 관리 관련

- 데이터의 생명주기는? (생성 → 수정 → 보관 → 삭제)
- 소프트 삭제(논리 삭제)가 필요한가, 하드 삭제인가?
- 데이터 보관 기간 요구사항이 있는가? (법적 의무 등)

### 검색/조회 관련

- 검색 범위와 필터 조건은?
- 전문 검색(Full-text search)이 필요한가?
- 정렬 기준과 페이지네이션 방식은?

### 알림/통지 관련

- 어떤 이벤트에 알림을 보내나?
- 알림 채널은? (이메일, SMS, 푸시, 인앱)
- 알림 설정을 사용자가 커스터마이즈할 수 있어야 하는가?

### 결제/거래 관련

- 사용할 PG사 또는 결제 수단은?
- 환불/취소 정책은?
- 정산 주기와 방식은?

## 3단계: 비기능 요구사항 — 기본값 제안

사용자가 구체적인 수치를 모를 때 참고할 수 있는 일반적인 기본값.

### 성능

| 규모 | 동시 접속 | API 응답 시간 | 페이지 로딩 |
|------|-----------|---------------|-------------|
| 소규모 (사이드 프로젝트) | 10~50명 | 1초 이내 | 3초 이내 |
| 중규모 (스타트업) | 100~500명 | 500ms 이내 | 2초 이내 |
| 대규모 (엔터프라이즈) | 1,000명 이상 | 200ms 이내 | 1초 이내 |

### 가용성

| 수준 | 가동률 | 연간 다운타임 | 적합한 경우 |
|------|--------|---------------|-------------|
| 기본 | 99% | ~3.65일 | 내부 도구, 사이드 프로젝트 |
| 표준 | 99.5% | ~1.83일 | 일반 웹 서비스 |
| 높음 | 99.9% | ~8.77시간 | 커머스, SaaS |
| 매우 높음 | 99.99% | ~52.6분 | 금융, 의료 |

### 보안 — 체크리스트

인터뷰 시 빠뜨리기 쉬운 보안 항목:

- [ ] HTTPS 필수 여부
- [ ] 개인정보 암호화 범위 (비밀번호, 연락처, 결제 정보 등)
- [ ] API 인증 방식 (JWT, OAuth2, API Key 등)
- [ ] CORS 정책
- [ ] Rate Limiting
- [ ] 감사 로그 (누가 언제 무엇을 했는지)
- [ ] GDPR/개인정보보호법 준수 여부

## 4단계: 인터페이스 — 확인 사항

### REST API 인터페이스

- 인증 토큰 전달 방식은? (Header, Cookie, Query Parameter)
- 에러 응답 형식은 표준화되어 있는가?
- API 문서화 도구를 사용하는가? (Swagger/OpenAPI 등)

### 메시지 큐 / 이벤트 기반

- 어떤 메시지 브로커를 사용하는가? (Kafka, RabbitMQ, SQS 등)
- 메시지 순서 보장이 필요한가?
- 메시지 유실 시 재처리 전략은?

### 데이터베이스

- RDBMS / NoSQL / 혼합 중 어떤 전략인가?
- 읽기/쓰기 분리가 필요한가?
- 캐싱 전략은? (Redis, Memcached 등)
