# Claude 모델 선택 가이드

> **난이도**: 기초 | **선행 문서**: 없음
>
> Opus, Sonnet, Haiku — 세 모델의 특성을 이해하고 상황에 맞는 모델을 선택하는 방법을 다룬다.

---

## 1. Claude 모델 패밀리 개요

Anthropic은 하나의 단일 모델 대신 용도에 따라 최적화된 세 모델 라인을 운영한다. 2026년 3월 현재 최신 세대는 Claude 4.x이며, 각 라인은 고유한 성능 특성과 비용 구조를 갖는다.

세 모델의 포지셔닝은 명확하다.

- **Opus**: 최고 지능. 복잡한 추론과 장시간 자율 작업에 특화된 플래그십 모델이다.
- **Sonnet**: 속도와 지능의 균형. 대부분의 개발 작업에서 실용적인 선택이다.
- **Haiku**: 최고 속도. 단순 반복 작업과 비용 최소화가 필요한 경우에 적합하다.

모델 이름에 붙는 숫자(4.5, 4.6)는 동일 라인 내 개선 버전을 뜻한다. Sonnet 4.6이 Sonnet 4.5보다 추론 품질이 향상되었듯이, 높은 숫자가 더 최신 버전이다.

---

## 2. 모델 비교표

| 특성 | Opus 4.6 | Sonnet 4.6 | Haiku 4.5 |
|---|---|---|---|
| API 모델명 | `claude-opus-4-6` | `claude-sonnet-4-6` | `claude-haiku-4-5-20251001` |
| 컨텍스트 윈도우 | 1M 토큰 | 1M 토큰 | 200k 토큰 |
| 최대 출력 | 128k 토큰 | 64k 토큰 | 64k 토큰 |
| 응답 속도 | 중간 | 빠름 | 매우 빠름 |
| Extended/Adaptive Thinking | 지원 | 지원 | 미지원 |
| 지식 기준일 | 2025년 5월 | 2025년 8월 | 2025년 2월 |

컨텍스트 윈도우 차이가 실무에서 가장 크게 체감되는 부분이다. Haiku의 200k는 일반 문서 처리에는 충분하지만, 대규모 코드베이스 전체를 한 번에 다뤄야 할 때는 Opus나 Sonnet의 1M 컨텍스트가 필요하다.

지식 기준일도 선택에 영향을 줄 수 있다. 최신 라이브러리나 프레임워크에 대한 질문이라면, 2025년 8월을 기준으로 하는 Sonnet 4.6이 Haiku 4.5보다 더 정확한 답을 줄 가능성이 높다.

---

## 3. 상황별 선택 가이드

### Opus를 선택할 때

Opus는 문제가 복잡하고 오답의 비용이 높은 상황에 쓴다.

- 여러 파일에 걸친 대규모 리팩토링
- 시스템 아키텍처 설계와 트레이드오프 분석
- 장시간 실행되는 에이전트 작업 (여러 단계를 스스로 판단하며 진행하는 작업)
- 대용량 문서나 코드베이스를 한 번에 분석해야 하는 경우
- 심화 보안 리뷰나 성능 병목 원인 분석

예를 들어 레거시 모놀리식 시스템을 마이크로서비스로 분리하는 작업이라면 Opus가 적합하다. 의존성 추적, 경계 식별, 마이그레이션 순서 결정 등 여러 판단이 연쇄적으로 이어지기 때문이다.

### Sonnet을 선택할 때

Sonnet은 대부분의 일상적인 개발 작업에서 충분하다.

- 새 기능 구현, 버그 수정, 코드 리뷰
- REST API 작성, 데이터베이스 쿼리 최적화
- 실시간 응답이 필요한 챗봇이나 대화형 인터페이스
- 테스트 코드 작성과 문서화
- Extended Thinking이 필요하지만 Opus 비용을 감수하기 어려운 경우

실제로 oh-my-claudecode 같은 멀티에이전트 프레임워크에서 Sonnet은 "실행 에이전트(executor)"의 기본 모델로 쓰인다. 지능과 속도 모두 실용적인 수준이기 때문이다.

### Haiku를 선택할 때

Haiku는 처리량이 많고 응답 속도가 중요하며 각 작업이 단순할 때 쓴다.

- 텍스트 분류, 감정 분석, 키워드 추출
- 대량 데이터 전처리 파이프라인
- 사용자 입력의 1차 파싱 (의도 파악, 라우팅)
- 비용 예산이 엄격한 고처리량 배치 작업

예를 들어 하루 수백만 건의 고객 리뷰를 분류하는 작업이라면 Haiku가 적합하다. Opus로 같은 작업을 돌리면 정확도는 비슷하지만 비용이 몇 배 높아진다.

## 4. Effort 파라미터 (Adaptive Thinking)

Claude 4.6 모델(Opus, Sonnet)은 `effort` 파라미터로 추론 깊이를 제어할 수 있다. 모델이 답변을 생성하기 전에 내부적으로 얼마나 오래 "생각"할지를 지정하는 방식이다.

| 값 | 용도 |
|---|---|
| `low` | 빠른 응답이 필요한 단순 질문, 사실 확인 |
| `medium` | 일반 개발 작업, 코드 작성 (기본값) |
| `high` | 복잡한 추론, 다단계 문제 해결 |
| `max` | 가장 어려운 수학·논리 문제, 최대 정확도 필요 시 |

`effort`가 높을수록 응답 시간이 길어지고 토큰 소비가 늘어난다. 단순한 작업에 `max`를 쓰면 비용 낭비다.

API 호출 예시:

```python
import anthropic

client = anthropic.Anthropic()

response = client.messages.create(
    model="claude-sonnet-4-6",
    max_tokens=8000,
    thinking={
        "type": "enabled",
        "budget_tokens": 5000
    },
    messages=[{
        "role": "user",
        "content": "이 알고리즘의 시간 복잡도를 분석하고 최적화 방안을 제시해줘."
    }]
)
```

`budget_tokens`는 내부 추론(thinking)에 허용할 최대 토큰 수다. 이 값이 클수록 더 깊이 생각하지만 그만큼 시간과 비용이 든다. Extended Thinking에 대한 자세한 내용은 `05-extended-thinking.md`에서 다룬다.

## 5. Claude Code에서의 모델 선택

Claude Code는 기본적으로 Claude Opus 4.6을 사용한다. 대화형 코딩 작업에서 높은 추론 품질이 필요한 경우가 많기 때문이다.

모델 변경 방법은 두 가지다.

- `/model` 명령어: 대화 중 원하는 모델로 전환한다.
- `Alt+P` 단축키: 모델 선택 패널을 빠르게 열 수 있다.

**Fast 모드**는 동일한 Opus 4.6 모델을 사용하지만 출력 속도를 높이는 옵션이다. 내부적으로 응답 스트리밍 방식을 조정하여 첫 토큰이 나오는 속도를 줄인다. 빠른 피드백이 필요한 반복 작업에 유용하다.

oh-my-claudecode 같은 멀티에이전트 환경에서는 에이전트별로 다른 모델을 지정할 수 있다. 예를 들어 탐색(explore) 에이전트에는 Haiku를, 구현(executor) 에이전트에는 Sonnet을, 아키텍처 리뷰(architect) 에이전트에는 Opus를 지정하는 방식이다.

```python
# Task 호출 시 model 파라미터로 지정
Task(
    subagent_type="oh-my-claudecode:executor",
    model="sonnet",
    prompt="로그인 기능 구현"
)
```

이 패턴을 쓰면 작업 성격에 맞는 모델을 쓰면서도 전체 비용을 통제할 수 있다.

## 6. 비용 최적화 팁

모델 선택이 곧 비용 구조를 결정한다. 같은 작업을 Opus로 처리하면 Haiku 대비 수십 배 비용이 들 수 있다.

**작업 복잡도에 맞는 모델 매핑**이 핵심 원칙이다. Opus의 추론 능력이 필요 없는 단순 작업에 Opus를 쓰는 것은 낭비다. 반대로 Haiku로 복잡한 추론을 시키면 오답이 나와 재작업 비용이 더 들 수 있다.

**전처리-심화 파이프라인 패턴**이 실무에서 자주 쓰인다.

1. Haiku로 대량의 원시 데이터를 필터링·분류·정제한다.
2. 걸러진 핵심 데이터만 Opus나 Sonnet에 넘겨 심화 분석한다.

예를 들어 1,000개의 고객 피드백에서 심각한 버그 리포트만 추려내는 경우, Haiku로 1차 분류 후 Opus로 심층 분석하면 Opus를 전체에 적용하는 것보다 비용을 크게 줄일 수 있다.

**effort 파라미터 활용**도 비용 최적화 수단이다. Sonnet이나 Opus를 써야 하는 상황이더라도, 단순한 질문에는 `effort: low`로 추론 깊이를 제한하면 토큰 소비를 줄일 수 있다.

가격 정보는 시점에 따라 변동되므로 공식 문서를 참고한다. [Anthropic 가격 페이지](https://www.anthropic.com/pricing)에서 현재 기준 요금을 확인할 수 있다.

## 7. 핵심 정리

**한 줄 결론**: 작업의 복잡도와 속도 요구에 맞춰 선택하라.

빠른 선택 가이드:

- 복잡한 추론, 대규모 작업, 최고 품질 필요 → **Opus 4.6**
- 일반 개발 작업, 실시간 응답, 비용과 품질 균형 → **Sonnet 4.6**
- 단순 반복, 고처리량, 비용 최소화 → **Haiku 4.5**

모델은 고정하지 않고 작업 성격에 따라 유연하게 바꾸는 것이 좋다. Claude Code의 `/model` 명령어나 멀티에이전트 프레임워크의 `model` 파라미터를 활용하면 워크플로우 안에서 모델을 자유롭게 조합할 수 있다.
