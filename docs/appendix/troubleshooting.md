# 자주 겪는 문제와 해결법

> **난이도**: 전체 | **선행 문서**: 없음
>
> Claude와 Claude Code 사용 중 흔히 발생하는 문제의 원인과 해결 방법을 정리한다.

---

## 1. 설치 및 인증 문제

### Claude Code가 설치되지 않음

**증상**: 설치 스크립트 실행 후 `claude` 명령이 인식되지 않거나, Windows에서 설치 도중 오류가 발생한다.

**원인**: Windows에서 Claude Code는 내부적으로 git 명령을 사용한다. Git for Windows가 설치되어 있지 않으면 설치 과정이 완료되더라도 실행이 되지 않는다.

**해결**:

1. [git-scm.com](https://git-scm.com)에서 Git for Windows를 내려받아 설치한다.
2. 설치가 끝나면 터미널을 새로 연다(기존 터미널은 PATH 변경을 반영하지 않는다).
3. Claude Code 설치를 다시 시도한다.

macOS와 Linux에서는 Node.js 버전이 맞지 않아 실패하는 경우가 많다. `node --version`으로 버전을 확인하고, 공식 요구 사양을 충족하지 못하면 Node.js를 먼저 업데이트한다.

---

### 로그인이 안 됨

**증상**: `claude` 또는 `/login`을 실행해도 브라우저 인증 화면이 열리지 않거나, 열리더라도 인증 완료 후 터미널에서 오류가 반환된다.

**원인**: 브라우저 쿠키나 캐시가 오래된 인증 정보를 유지하고 있어 OAuth(개방형 인증) 흐름이 막히는 경우가 많다. 네트워크 환경에서 방화벽이나 프록시가 인증 콜백을 차단하는 경우도 있다.

**해결**:

1. 세션 안에서 `/login`을 다시 실행한다.
2. 브라우저의 캐시와 쿠키를 삭제한 뒤 재시도한다.
3. 다른 브라우저로 시도한다.
4. 기업 네트워크나 VPN(가상 사설망) 환경이라면 외부 네트워크로 전환한 뒤 인증을 시도한다.
5. 위 방법이 모두 안 된다면 Anthropic Console에서 API 키를 발급받아 직접 입력하는 방식으로 전환한다.

---

### "Claude Code is not available" 오류

**증상**: 로그인은 됐는데 실행 시 Claude Code를 사용할 수 없다는 메시지가 표시된다.

**원인**: Claude Code는 모든 계정에서 사용 가능하지 않다. Pro, Max, Teams, Enterprise 구독이 필요하다. API 키로 접근하는 경우에는 크레딧 잔액이 소진됐을 가능성이 있다.

**해결**:

- claude.ai에서 현재 구독 플랜을 확인한다. Free 플랜에는 Claude Code가 포함되지 않는다.
- API 키를 사용 중이라면 Anthropic Console에서 크레딧 잔액을 확인하고, 필요하면 충전한다.
- 구독 중인데도 오류가 발생한다면 claude.ai에서 로그아웃 후 재로그인하거나, 터미널에서 `claude /logout` 후 다시 `/login`을 실행한다.

---

## 2. 프롬프트 관련 문제

### Claude가 지시를 무시함

**증상**: 분명히 요청했는데 Claude가 다른 방향으로 응답하거나, 특정 규칙을 일관성 없이 지킨다.

**원인**: 프롬프트가 모호하거나 너무 길어서 핵심 지시가 묻히는 경우다. Claude는 요청 전체를 보고 가장 그럴듯한 의도를 추론하는데, 이 추론이 의도와 다를 수 있다.

**해결**:

- 지시를 더 구체적으로 작성한다. "개선해줘" 대신 "변수명만 더 명확하게 바꿔줘. 로직은 건드리지 마"처럼 범위와 제약을 명시한다.
- 반복적으로 지켜야 하는 규칙은 `CLAUDE.md`에 추가한다. CLAUDE.md는 프로젝트 루트에 위치하며 세션마다 자동으로 읽히기 때문에, 매번 프롬프트에 반복할 필요가 없다.
- 한 번에 너무 많은 것을 요청하지 않는다. 작업을 쪼개서 순서대로 진행하면 각 단계의 품질이 높아진다.

---

### 응답이 갑자기 짧아짐

**증상**: 대화가 길어질수록 Claude의 응답이 점점 간략해지거나, 앞서 작성한 코드나 내용을 기억하지 못한다.

**원인**: 컨텍스트 윈도우(context window — 모델이 한 번에 처리할 수 있는 텍스트의 최대 길이)가 가득 찬 것이다. 컨텍스트가 꽉 차면 가장 오래된 내용부터 밀려나기 시작하고, 응답 품질이 떨어진다.

**해결**:

- `/compact`를 실행한다. 현재 대화 내용을 요약해서 컨텍스트를 압축한다. 맥락은 유지하면서 토큰을 절약할 수 있다.
- 완전히 새로 시작해야 한다면 `/clear`로 컨텍스트를 초기화한다.
- 다음 세션에서 이전 맥락이 필요하다면 `-c` 플래그(`claude -c`)로 대화를 이어서 시작하거나, 핵심 정보를 CLAUDE.md에 기록해두는 방법이 있다.

---

### 같은 실수를 반복함

**증상**: 한 번 수정을 요청했는데 다음 세션에서 같은 문제가 반복된다. 또는 대화 안에서도 같은 잘못을 계속 한다.

**원인**: Claude는 세션이 끝나면 이전 대화를 기억하지 않는다. 대화 중에 반복되는 경우는 모호한 수정 요청을 일회성으로 처리하고 근본 규칙으로 삼지 않기 때문이다.

**해결**:

- 세션을 넘어서도 지켜야 하는 규칙은 `CLAUDE.md`에 추가한다. "한국어로 응답할 것", "커밋 메시지는 영어로 작성할 것"처럼 명시적으로 적는다.
- 세션 내에서 반복되는 문제라면 `/memory`로 자동 메모리 기능을 활성화하거나, 대화 초반에 규칙 목록을 명시적으로 전달한다.

---

## 3. Claude Code 동작 문제

### 파일을 찾지 못함

**증상**: "파일이 없다"는 오류가 발생하거나, 분명히 존재하는 파일을 Claude Code가 인식하지 못한다.

**원인**: Claude Code는 실행 시점의 작업 디렉토리(current working directory)를 기준으로 파일을 탐색한다. 프로젝트 루트가 아닌 다른 위치에서 실행하면 파일 경로가 맞지 않는다.

**해결**:

1. 터미널에서 `pwd`(현재 디렉토리 확인 명령)를 실행해 현재 위치를 확인한다.
2. 프로젝트 루트로 이동한 뒤 `claude`를 다시 실행한다.

```bash
cd /path/to/my-project
claude
```

---

### 권한 프롬프트가 너무 자주 뜸

**증상**: 파일을 읽거나 명령을 실행할 때마다 허용 여부를 묻는 화면이 반복해서 나타난다.

**원인**: 기본(default) 모드에서는 시스템에 영향을 주는 모든 작업 전에 사용자 확인을 요청한다. 이는 의도된 동작이지만, 반복 작업 시 불편할 수 있다.

**해결**:

- 세션 중 `Shift+Tab`을 눌러 권한 모드를 전환한다. auto 모드로 바꾸면 Claude가 안전하다고 판단한 작업은 확인 없이 진행한다.
- 특정 도구를 항상 허용하려면 설정 파일에 `allowedTools`를 추가한다.

```json
{
  "permissions": {
    "allow": ["Bash(git:*)", "Read", "Write"]
  }
}
```

글로벌 설정(`~/.claude/settings.json`)에 추가하면 모든 프로젝트에 적용되고, 프로젝트 설정(`.claude/settings.json`)에 추가하면 해당 프로젝트에만 적용된다.

---

### Hook이 작동하지 않음

**증상**: `settings.json`에 훅(hook — 특정 이벤트 발생 시 자동으로 실행되는 스크립트)을 설정했는데 실행되지 않는다.

**원인**: JSON 문법 오류가 가장 흔한 원인이다. 쉼표 누락, 중괄호 불일치, 문자열 따옴표 오류 등이 있다. matcher 필드의 정규식(regular expression — 패턴 매칭에 쓰이는 표현식)이 잘못 작성된 경우도 많다.

**해결**:

1. `/hooks`를 실행해 현재 등록된 훅 목록과 상태를 확인한다.
2. `settings.json` 파일을 JSON 검증 도구(예: jsonlint.com)에 붙여넣어 문법 오류를 찾는다.
3. 정규식을 사용했다면 별도 테스터로 패턴이 의도한 대로 동작하는지 확인한다.
4. 훅에서 실행하는 명령의 절대 경로가 올바른지 점검한다. 환경에 따라 `bash`, `python` 등의 경로가 달라질 수 있다.

---

### MCP 서버 연결 실패

**증상**: MCP(Model Context Protocol — 외부 도구와 Claude를 연결하는 프로토콜) 서버를 설정했는데 "연결할 수 없다"거나 도구 목록에 나타나지 않는다.

**원인**: 서버 실행 명령의 경로가 잘못됐거나, 서버가 의존하는 환경 변수가 설정되지 않은 경우가 많다. 서버 프로세스 자체가 시작에 실패하면 Claude Code는 아무런 도구도 받지 못한다.

**해결**:

1. `claude mcp list`로 현재 등록된 MCP 서버 목록과 상태를 확인한다.
2. `--mcp-debug` 플래그를 붙여 실행하면 서버 연결 과정의 상세 로그를 볼 수 있다.

```bash
claude --mcp-debug
```

3. 서버 실행 명령을 터미널에서 직접 실행해 오류 메시지를 확인한다.
4. 필요한 환경 변수(API 키, 토큰 등)가 설정되어 있는지 점검한다. `settings.json`의 `env` 항목에 직접 추가하는 방법도 있다.

## 4. 성능 관련 문제

### 응답이 느림

**증상**: 요청을 보낸 뒤 응답이 나오기까지 평소보다 훨씬 오래 걸린다.

**원인**: 컨텍스트가 너무 크거나, 복잡한 추론이 필요한 작업이거나, 대용량 파일을 통째로 읽는 경우 응답 시간이 길어진다. 네트워크 상태가 좋지 않을 때도 마찬가지다.

**해결**:

- `/compact`로 컨텍스트를 줄인다. 현재 컨텍스트가 크면 큰 만큼 처리 시간이 늘어난다.
- 파일 전체를 읽도록 요청하는 대신 필요한 부분만 지정한다. "전체 코드베이스를 분석해줘" 대신 "src/api/auth.js의 토큰 검증 로직만 봐줘"처럼 범위를 좁힌다.
- `/fast` 명령으로 Fast 모드로 전환한다. Fast 모드는 동일한 모델을 사용하지만 출력 속도를 높이는 옵션이다. 모델 자체가 바뀌는 것이 아니므로 추론 품질은 유지된다.

---

### 컨텍스트 윈도우 관리

컨텍스트가 쌓이면서 나타나는 증상은 단계적으로 달라진다. 상황에 맞는 대응법을 선택한다.

| 증상 | 원인 | 권장 대응 |
|---|---|---|
| 응답이 점점 짧아지고 간략해진다 | 컨텍스트가 절반 이상 찼다 | `/compact` 실행 |
| 앞에서 작성한 코드를 기억하지 못한다 | 오래된 내용이 밀려남 | `/compact` 후 핵심 내용 재요약 |
| 완전히 다른 방향의 응답이 나온다 | 컨텍스트 혼재 | `/clear` 후 새 세션 시작 |
| 응답 중간에 Esc 키를 눌러 중단했다 | 작업 취소 | Esc 두 번으로 편집 모드 진입 후 재작성 |

세 가지 초기화 수단의 차이를 명확히 구분한다.

- `/compact`: 대화를 요약하여 압축한다. 맥락은 유지된다. 대화가 길어졌지만 이어서 작업해야 할 때 사용한다.
- `/clear`: 컨텍스트를 완전히 초기화한다. 새로운 작업을 처음부터 시작할 때 사용한다.
- Esc + Esc: 현재 입력 중인 메시지를 취소한다. 컨텍스트는 그대로 유지된다. 잘못 작성한 요청을 보내지 않고 수정할 때 사용한다.

## 5. 핵심 정리

문제가 생겼을 때 당황하지 않으려면 점검 순서를 정해두는 것이 좋다.

**문제 해결 순서**

1. **증상 확인**: 오류 메시지를 그대로 읽는다. 대부분의 오류 메시지에 원인이 담겨 있다.
2. **원인 파악**: 설치, 인증, 설정, 성능 중 어느 범주의 문제인지 분류한다.
3. **해결 시도**: 해당 범주의 해결법을 순서대로 시도한다.
4. **재시작**: 해결이 안 되면 터미널을 완전히 닫고 새로 연다. 환경 변수나 PATH 변경이 반영되지 않아서 생기는 문제가 의외로 많다.

**자주 통하는 원칙**: 대부분의 동작 이상은 `/clear`로 해결된다. 대화가 이상하게 흘러가거나 Claude가 일관성 없는 응답을 반복한다면, 컨텍스트를 초기화하고 핵심 요청만 다시 전달하는 것이 가장 빠른 해결책이다. 설치나 인증 문제라면 터미널 재시작과 로그아웃 후 재로그인이 그에 해당하는 초기화다.
