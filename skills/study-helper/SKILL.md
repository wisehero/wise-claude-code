# Study Helper

노션에 정리한 기술 학습 노트를 검수하여, AI투(AI 냄새) 제거 · 오타 수정 · 팩트체크를 수행하고 검수 리포트를 제공하는 스킬.

## 워크플로우

```
노션 페이지 이름 입력
    ↓
[1단계] 노션 페이지 내용 가져오기 (Notion 도구)
    ↓
[2단계] /humanizer — AI투 제거 + 오타 수정
    ↓
[3단계] /external-context — 팩트체크 (웹 검색 기반)
    ↓
[4단계] 검수 리포트 생성
    ↓
[5단계] 터미널 출력 (기본) / 파일 저장 (요청 시)
```

---

## 상세 단계

### 1단계: 노션 페이지 내용 가져오기

사용자로부터 **노션 페이지 이름**을 입력받는다.

1. Notion 검색 도구로 해당 페이지를 찾는다.
2. Notion fetch 도구로 페이지 전체 내용을 가져온다.
3. 페이지 내용을 `original_content` 변수로 보관한다 (비교용).

**페이지를 찾지 못한 경우**: 유사한 이름의 페이지 목록을 제시하고 사용자에게 선택을 요청한다.

---

### 2단계: AI투 제거 + 오타 수정 (/humanizer)

`/humanizer` 스킬을 호출하여 다음을 수행한다:

- **AI투 제거**: 과도한 구조화, 뻔한 서론/결론, 불필요한 강조 등 AI가 작성한 티가 나는 표현을 자연스러운 문체로 수정
- **오타 수정**: 맞춤법, 띄어쓰기, 오탈자 교정

이 단계의 결과를 `humanized_content`로 보관한다.

**변경 사항 추적**: 수정된 부분마다 아래 정보를 기록한다:

- 원본 텍스트
- 수정된 텍스트
- 수정 유형 (AI투 / 오타)
- 수정 이유 (간결하게)

**humanizer 호출 실패 시**: 사용자에게 실패를 알리고, AI투/오타 수정 없이 팩트체크 단계로 넘어간다. 리포트의 "AI투 제거 & 오타 수정" 섹션에 "humanizer 호출 실패로 미수행"을 명시한다.

---

### 3단계: 팩트체크 (/external-context)

`/external-context` 스킬을 호출하여 기술적 사실관계를 검증한다.

#### 검증 대상

- 프레임워크/라이브러리의 동작 방식 설명
- API 사용법, 메서드 시그니처
- 아키텍처 패턴, 디자인 패턴의 정의와 적용 방식
- 설정값, 기본값, 기본 동작
- 버전별 차이점이나 변경 사항

#### 버전 기준 원칙

> **현재 시점에서 실용적인 버전만 다룬다.**

- 검증 기준은 **현재 널리 사용되는 최신 안정 버전**(Latest Stable)이다.
- 과거 버전은 **해당 내용이 이미 노트에 언급된 경우에만** 간략히 보완한다.
  - 예: "Spring Boot 2.x에서는 이랬지만 3.x에서 변경됨" 정도의 한 줄 언급
- 노트에 없는 레거시 내용을 새로 추가하지 않는다.
- **절대 하지 말 것**: 현재 시대에 의미 없는 구버전(예: Spring 4.3, Java 8 이전, Redis 5 이전 등)을 메인 내용으로 설명

#### 팩트체크 결과 기록

각 검증 항목마다:

- 원본 내용 (요약)
- 검증 결과: ✅ 정확 / ⚠️ 부분 수정 필요 / ❌ 오류
- 근거 (참고 소스 URL 포함)
- 수정 제안 (필요한 경우)

**external-context 호출 실패 시**: 사용자에게 실패를 알리고, 팩트체크 없이 리포트를 생성한다. 리포트의 "팩트체크 결과" 섹션에 "external-context 호출 실패로 미수행"을 명시한다.

---

### 4단계: 검수 리포트 생성

`references/report-template.md` 템플릿에 따라 검수 리포트를 구성한다.

---

### 5단계: 출력

- **기본 동작**: 리포트 내용을 터미널에 바로 출력한다.
- **파일 저장**: 사용자가 별도로 요청한 경우에만 `.md` 파일로 저장한다. 파일명은 `검수리포트_[페이지제목]_YYYYMMDD.md` 형식을 따른다.

## Examples

### 예시 1: 기본 사용

```
사용자: "Spring MVC 정리한 노션 페이지 검수해줘"
동작:
  1. "Spring MVC" 키워드로 노션 검색 → 페이지 fetch
  2. /humanizer로 AI투 제거 + 오타 수정
  3. /external-context로 팩트체크
  4. 터미널에 리포트 출력
```

### 예시 2: 파일 저장 요청

```
사용자: "JPA 학습 노트 검수하고 파일로 저장해줘"
동작:
  1~4단계 동일
  5. 검수리포트_JPA_20260310.md 파일로 저장
```

### 예시 3: 페이지명이 모호한 경우

```
사용자: "Redis 정리한 거 검수 좀"
동작:
  1. "Redis" 검색 → 유사 페이지 3개 발견
  2. 사용자에게 목록 제시: "Redis 캐싱 전략", "Redis Pub/Sub", "Redis 자료구조"
  3. 사용자 선택 후 진행
```

## Troubleshooting

**노션 페이지가 너무 긴 경우**
- 원인: Notion fetch 도구의 응답 크기 제한
- 해결: 페이지를 섹션별로 나누어 검수하겠다고 사용자에게 안내 후, 주요 섹션부터 순차 처리

**동일 이름 페이지가 여러 개인 경우**
- 원인: 노션 워크스페이스에 같은 제목의 페이지 존재
- 해결: 검색 결과에 상위 페이지(부모) 경로를 함께 표시하여 구분

**humanizer나 external-context 스킬을 찾을 수 없는 경우**
- 원인: 해당 스킬이 설치되지 않았거나 비활성 상태
- 해결: 사용자에게 필요한 스킬 설치를 안내하고, 해당 단계를 건너뛰어 가능한 범위까지 리포트 생성

---

## 주의사항

1. **메인 내용을 건드리지 않는다**: 팩트체크로 발견된 오류를 수정 제안할 뿐, 학습 노트의 구조나 흐름을 바꾸지 않는다.
2. **보완은 최소한으로**: 보완 제안 섹션은 1~3개 이내로 제한하며, 각 항목은 한두 문장 수준이다.
3. **레거시 버전 깊이 파지 않기**: 과거 버전 설명은 "~에서는 ~였다" 수준의 간략한 언급만 허용한다.
4. **출처 명시**: 팩트체크 수정 제안에는 반드시 참고 소스(공식 문서 등)를 포함한다.
5. **원본 보존**: 원본 내용은 리포트에 그대로 인용하여 비교가 가능하도록 한다.
